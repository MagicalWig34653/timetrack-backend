# Dokumentation

Diese Seiten werden beim Bauen der Website aus den Dokumenten im Repository übernommen. Die Quelle bleibt das Repository; hier wird nichts doppelt gepflegt.

## Wo anfangen?

| Ich möchte … | Lies |
| --- | --- |
| verstehen, was Timetrack kann und was noch offen ist | [Konzept](/docs/konzept) |
| wissen, wie es technisch aufgebaut ist | [Architektur](/docs/architektur) und [Architekturentscheidungen](/adr/) |
| es lokal starten und testen | [Einrichtung](/docs/einrichtung) |
| es betreiben, sichern und wiederherstellen | [Betrieb](/docs/betrieb) |
| einen KI-Assistenten anbinden | [MCP-Anbindung](/docs/mcp) |
| die API ansprechen | [API-Referenz](/api/) |
| verstehen, wie gebaut, getestet und veröffentlicht wird | [CI und Pages](/docs/ci) |
| die Gestaltung nachvollziehen | [Designsprache](/docs/design) |

Der **Umsetzungsstand** steht in [Umsetzung](/docs/umsetzung). Die Dokumentationslandkarte des Repositories, die zusätzlich interne Arbeitsdokumente verzeichnet, liegt unter [`docs/README.md`](https://github.com/MagicalWig34653/timetrack-backend/blob/main/docs/README.md).
