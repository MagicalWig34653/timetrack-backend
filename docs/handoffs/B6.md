# Handoff B6 (Backend): Anhangzahl, Anhangfilter, Inline-Vorschau

Stand: 19.10.2026. Branch `worktree-agent-a0c3a2218a5ea8324` (auf main 9668ef6, Vertrag 0.23.0), nicht gepusht, nicht gemergt. Vertrag **v0.24.0**. Entscheidungen: ADR-0006 Nachtrag B6. Wünsche aus der PWA-Abwesenheitsliste (PWA-Handoff P5, offener Punkt 1 und Download-Disposition).

## Was gebaut ist
1. **`Absence.attachmentCount`** (additiv, Pflichtfeld in der Antwort): `GET/POST /absences`, `GET/PUT /absences/{id}` und MCP `list_absences`/`create_absence` (gleiches DTO). Zählt gespeicherte (`stored`), eigene Anhänge, also exakt die Menge von `GET /absences/{id}/attachments`; Dateien in `deleting`/`failed`/`pending` zählen nicht. Liste: eine aggregierte SQL-Abfrage (`AbsenceService.attachmentCounts`), kein N+1; Test belegt 9 Fluent-Abfragen sowohl bei 2 als auch bei 12 Abwesenheiten. Einzelabruf, Update und Create (immer 0) liefern das Feld ebenfalls. Wochen-, Plan- und Freigabeansichten betten `Absence` nicht ein, daher keine Änderung.
2. **`GET /absences?hasAttachment=true|false`**: sonstiger Wert 400 `bad_request`.
3. **`GET /files/{id}?disposition=inline`**: Whitelist image/png, image/jpeg, image/gif, image/webp, application/pdf, text/plain; dann `inline`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox; default-src 'none'`. Sonst Rückfall auf `attachment`. `FilenameSanitizer.isInlineSafe`, `contentDisposition(_:inline:)`.
4. Vertrag 0.24.0 (Schema, Parameter, Beschreibung, Changelog), JSON-Kopie neu erzeugt, `apiContractVersion` 0.24.0.

## Offene Fragen
1. Fehlercode für ungültiges `hasAttachment`: der Auftrag sagt "400 invalid", der Bestand kennt für ungültige Anfragen `bad_request` (`APIError.invalid`); ich habe `bad_request` genommen.
2. Der Cache-Control-Header der Downloadantwort wird von einer vorgelagerten Middleware auf `no-store` vereinheitlicht (der Handler setzt `private, no-store`); unverändert, der Test prüft nur `no-store`.
3. Bei Dateien im Zustand `pending`/`failed` mit Verknüpfung zählt die Zahl 0 (konsistent mit der Anhangliste); falls die PWA "Verknüpfungen" statt "lesbare Anhänge" meinte, wäre das eine andere Definition.
4. CSP `sandbox; default-src 'none'` kann in manchen Browsern den eingebauten PDF-Viewer im `<iframe>` einschränken (Chrome blockiert PDF unter `sandbox`); im Browser nicht geprüft. Falls nötig, für `application/pdf` auf `default-src 'none'` ohne `sandbox` lockern.
