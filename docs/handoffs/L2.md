# Handoff L2: Compose-Umgebung, Dockerfile, Dev-Skript

Branch `l2-compose-env`. Dateien: `Dockerfile`, `.dockerignore`, `compose.yaml`, `.env.example`,
`scripts/dev-env.sh`, `deploy/pwa-empty/.gitkeep`.

## Befehle (`scripts/dev-env.sh`)

`init` (erzeugt `.env` mit Zufallspasswörtern, falls fehlend), `up` (nur DB, wartet auf healthy),
`up-app` (DB + Backend, Profil `app`), `up-sqlite` (Profil `sqlite`, Einzelinstanz), `up-mail` (Mailpit),
`down` (ohne `-v`), `logs [service]`, `db-shell`, `status`, `build-multiarch` (amd64+arm64 als OCI-Archiv
in tmp-Verzeichnis, kein Push), `test-db` (wartet auf healthy, gibt `export MARIADB_TEST_*` aus; Root-Benutzer,
damit Tests eigene Wegwerf-Datenbanken anlegen können).

## Ports (alle nur 127.0.0.1)

MariaDB 13306, Backend 18080, Mailpit-UI 18025 (SMTP 1025 nur intern, Host `mailpit`). PWA-Dev 5173 gehört zu L1.
`app` und `sqlite` binden beide 18080 und sind gegenseitig exklusiv.

## Volumes

`timetrack-dev-db` (MariaDB), `timetrack-dev-sqlite` (SQLite-Datei unter `/data`). Netzwerk `timetrack-dev_default`.

## Image-Wahl

MariaDB: `mariadb:12.3` (ist 12.3.3-MariaDB-ubu2404, identisch zum Serverstand), utf8mb4 / utf8mb4_unicode_ci.
Swift: `swift:6.3-noble` (Build) und `swift:6.3-noble-slim` (Laufzeit); Manifeste für amd64 und arm64 vorhanden.
Laufzeit: Nutzer `timetrack` (uid 10001), `libsqlite3-0`, `ca-certificates`, `curl` (nur Healthcheck).
Mailpit: `axllent/mailpit:v1.29`.

## Verifiziert (Colima, ARM64)

- `init`, `up`: `.env` angelegt (chmod 600), DB nach ca. 6,5 s healthy; Version 12.3.3-MariaDB-ubu2404,
  `character_set_server=utf8mb4`, `collation_server=utf8mb4_unicode_ci`.
- Persistenz: Markertabelle in Wegwerf-Datenbank `tt_marker` angelegt, `down` + `up`, Zeile weiter vorhanden,
  Datenbank danach gelöscht.
- `db-shell` (Client im Container) verbindet als `timetrack@%` mit Datenbank `timetrack`.
- `test-db` gibt Exportzeilen aus; Port-Bindung nur `127.0.0.1:13306` per lsof bestätigt.
- `docker compose config` für alle Profile gültig; `docker build --check` ohne Warnungen.

## NICHT verifiziert (Blocker)

Die Image-Builds (arm64 nativ, amd64 unter Emulation, `build-multiarch`) konnten nicht ausgeführt werden:
Die Colima-VM hat 20 GiB Disk und nur ca. 243 MB frei (andere Projekte belegen sie); der erste Build brach beim
Entpacken von `swift:6.3-noble` mit "no space left on device" ab. Aufräumen fremder Images/Caches ist laut Auftrag
untersagt. Folglich sind Dockerfile-Build, Laufzeit-Image, `/health` (arm64 und amd64), `up-app`, `up-sqlite`
und Mailpit-Start ungetestet. Lösungsvorschlag (Entscheidung beim Nutzer): Colima-Disk vergrößern
(`colima stop && colima start --disk 60`, stoppt vorübergehend alle Container der VM) oder ungenutzte
fremde Images selbst entfernen. Danach `scripts/dev-env.sh up-app` und `build-multiarch` ausführen.
Dockerfile-Risiken: Binärname `App` (Produkt `App`), Resource-Bundles werden nur kopiert, falls vorhanden.

## Anforderungen an den Lead / C1

- Backend soll `PWA_STATIC_DIR` (Default `/srv/pwa`) als statisches Verzeichnis ausliefern (Fallback `index.html`
  für SPA-Routen, `/api/v1` und `/health` haben Vorrang). Compose mountet `PWA_STATIC_HOST_DIR` read-only dorthin;
  Node ist zur Laufzeit nicht nötig.
- Backend soll die Konfigurationsschlüssel aus ADR-0003 plus `SMTP_HOST`/`SMTP_PORT` lesen; Compose setzt alle.
- Container startet `App serve --env production --hostname 0.0.0.0 --port 8080`; Healthcheck `GET /health`.
- Migrationen: `AUTO_MIGRATE=true` in Dev; Produktion sollte `false` und explizites `migrate` nutzen.
- WebAuthn lokal: RP-ID `localhost`, Origin `http://localhost:18080`.
- Für Tests: `eval "$(scripts/dev-env.sh test-db | grep ^export)"`.
