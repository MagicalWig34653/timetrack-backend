# P14 – APNs-Push (Backend)

Stand: 26.10.2026, Branch `p14-apns` (von `main` 0fc068a). Vertrag `0.33.0`, Migration `p14.create_apns_devices`, Entscheidung ADR-0030.

## Umgesetzt

- **Registrierung:** `GET/POST /api/v1/me/push-devices`, `DELETE .../{id}`, `POST .../{id}/test` (Sitzung + CSRF; Bearer-Token und Wiederherstellungssitzungen abgewiesen, MCP ohne Werkzeug). Token hexadezimal 64 bis 200 Zeichen, `platform ios|macos|watchos`, `environment sandbox|production`, `appBundleId` aus `APNS_BUNDLE_IDS`, `label` bis 100 Zeichen. Höchstens 10 Geräte (409), 30 Registrierungen und 5 Tests je Stunde (429). Token im Klartext (APNs braucht ihn) plus `token_hash` (eindeutig), nie in Antworten oder Logs (Begründung ADR-0030). Token eines anderen Kontos wechselt zum aufrufenden Konto.
- **Client:** `Notifications/Apns.swift`: `ApnsConfiguration` (`APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_PRIVATE_KEY` PEM, `APNS_BUNDLE_IDS`), `ApnsTokenProvider` (ES256-JWT, 50 Minuten Wiederverwendung), Protokoll `ApnsTransport` (der Name `PushTransport` gehört Web Push), `HTTP2ApnsTransport` (AsyncHTTPClient, HTTP/2 per ALPN, keine neue Abhängigkeit), `ApnsSender` mit Fehlerabbildung. Ohne vollständige Konfiguration bleibt APNs aus (Warnung nur bei Teilkonfiguration, `apnsAvailable:false`, Registrierung 501).
- **Zustellung:** `Notifications/ApnsDevices.swift`: Tabellen `apns_devices`, `apns_outbox`, `ApnsDispatcher` im Scheduler (`NotificationScheduler.runOnce`, gleiche Sperre wie Web Push), Einreihen in `emit` mit Ruhezeit-Aufschub, Prüfung von Kategorie-`push`, Modul und Kontosperre beim Einreihen und Senden, Backoff 1/5 Minuten, 3 Versuche. 410, 400 `BadDeviceToken`, `Unregistered` löschen das Gerät samt Warteschlange. Stiller Push `ApnsDispatcher.sendSyncHint` (noch ohne Auslöser).
- **Konto:** `AccountEraser` löscht Geräte und Warteschlange (Löschen, Sperren).
- **Logs:** `TriggerTokenScrubber` schwärzt zusätzlich Hex-Token (ab 64 Zeichen), PEM-Schlüssel und JWTs.
- **Doku:** ADR-0030, ARCHITEKTUR Abschnitt 7, EINRICHTUNG, `.env.example`, `compose.yaml`, `docs/installation/konfiguration.md`, LIZENZEN (keine neue Abhängigkeit), CHANGELOG, OpenAPI 0.33.0 (`PushDeviceInfo`, `PushConfig.apnsAvailable`), `scripts/docker-entrypoint.sh` (`APNS_PRIVATE_KEY_FILE`).

## Nicht geprüft / offen

Keine echte APNs-Verbindung (weder Sandbox noch Produktion), also auch HTTP/2-Aushandlung, Header-Annahme und Provider-Token gegen Apple ungeprüft. MariaDB nicht geprüft. Auslöser für den stillen Sync-Push, Secret-Verdrahtung in `deploy/`, Anbindung in den Apple-Apps (Registrierung, Berechtigung, Tippen auf die Mitteilung via `url`/`notificationId`), keine Wartungsbereinigung nach Zeit.
